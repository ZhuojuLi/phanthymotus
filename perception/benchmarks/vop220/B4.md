# B4: frozen B3 one-to-many detector, JP6 experiment

B4 retains B3's trained YOLOE-26m 220-class weights and 640 input. It selects the
one-to-many branch, keeps the highest class per anchor, applies class-aware NMS
at IoU 0.7, and defaults to confidence 0.35. No training or vocabulary changes.
Engine metadata explicitly selects dense decoding; legacy end-to-end engines
retain their previous decoding behavior. Photo and ROS2 stream use the same path.

The deployment contains 20,519,072 fused parameters. The TensorRT 10.4 FP16 engine
is built on Orin, downloaded through the versioned model bundle, and verified
by size and SHA256. Models are not stored in this repository. Use JP_VERSION=6;
this candidate does not provide a JP5 engine.

Validation on the frozen 107-image organizer development split (IoU >=0.7):

| Backend / configuration | TP | FP | FN | F1 |
|---|---:|---:|---:|---:|
| PyTorch B3, no extra NMS, conf .25 | 411 | 477 | 551 | .444324 |
| PyTorch B3, class-aware NMS, conf .25 | 411 | 457 | 551 | .449180 |
| PyTorch B4, conf .35 | 406 | 394 | 556 | .460840 |
| ONNX Runtime CPU numeric check, B4 | 407 | 393 | 555 | .461975 |
| JP6 TensorRT B3, no extra NMS | 410 | 481 | 552 | .442526 |
| JP6 TensorRT B3 outputs, class-aware NMS replay | 410 | 460 | 552 | .447598 |
| JP6 TensorRT B4, direct and MCP photo | 406 | 395 | 556 | .460579 |

The development set has been reused for model/threshold selection; these are not
independent test or leaderboard scores. Baseline platform F1 remains .4601 until
another submission is evaluated. B4's gain is the combination of branch, label
selection, NMS, and confidence changes, not an isolated architecture effect.

110 decoder/plugin tests pass. JP6 cold download, cache restart, photo, ROS2
stream start/stop, 107 MCP photo requests, and two independent service containers
pass. Testing used a code overlay on the existing JP6 runtime image; it did not
rebuild all base-image dependencies. The 8GB shared test box is not the platform's
16GB ten-instance environment. No claim of JP5 or ten-instance acceptance.

The initial deployment uses NumPy CPU NMS. On the test box, B4 direct image
preprocessing through detections had ~65 ms median, including ~13 ms decoding/NMS;
output transfer sampled separately was about 1 ms. MCP photo107 median/p95 was
157/1517 ms, versus B3 152/1462 ms. Includes decoding, colors and service overhead;
shared-device variation prevents a stable acceleration claim.

Whole-device tegrastats at 100 ms intervals measured B4 mean GPU ~3.8% at 1 request/s,
~13.8% during a requested 5 request/s sequential load (achieved ~3.62/s), peak 99%.
These facts do not demonstrate compliance with an unspecified <10% GPU rule.
Single-container sampled memory was ~356 MiB; Jetson uses shared memory.
The candidate is suitable for an isolated platform experiment, not a claim that
all platform resource limits or production acceptance have been met.
