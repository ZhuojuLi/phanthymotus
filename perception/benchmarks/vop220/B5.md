# B5: 70% B4 + 30% organizer epoch2 weight interpolation

This candidate interpolates 70% of B4's parameters with 30% of its organizer-only
epoch2 continuation. It deploys one fused YOLOE-26m detector with 20,519,072
parameters. The 220-class vocabulary, 640 input, FP16, one-to-many head,
highest class per anchor, class-aware NMS IoU .7, confidence .35 and max300
detections retain B4's deployment settings.

The frozen checkpoint SHA256 is
`775f6a6568c30c4227a89ad1ad05fc7aecfedf73396ea90aeab733de4ba64901`.
The ONNX SHA256 is
`985b9919f92436bb749b21b9ccb899ae20c52d979ed91b10f703bce4f4a94370`.
Separate TensorRT engines are built on the actual JP5 and JP6 Orin targets.
The downloader selects the matching family and verifies size and SHA256.
Models are distributed through versioned JuiceFS HTTP paths outside Git.

and JP6 tested; the platform run is configured for JP_VERSION=6.

Cold HTTP download with pinned hashes, cache restart, confidence override,
220-class vocabulary, configurable MCP/WS ports, and ROS2 stream start/stop
passed on both targets.155 local decoder/plugin/color/downloader tests passed.
The actual runtime sources were copied onto cached release.261030 perception
images; this validates the code and target runtime, not a complete base-image
rebuild. Runtime source hashes are retained for comparison with the published
commit.

These include full-size image color statistics and shared-host variation;
they are not platform FPS. The5785x3763 image alone needs about498MiB for the

during the initial attempt, so final JP5 measurements were taken after that
